# 布局与交互层次

## 桌面 Web 与窄屏

- 默认按桌面任务效率、信息密度和多区域布局设计，产品明确面向其他设备时例外；Tailwind mobile-first 写法不改变产品优先级。
- 列表和工作区合理利用宽屏，阅读内容和短表单限制行宽；不把桌面应用困在手机容器中，也不为填满空间增加无用模块。
- 窄屏通过收纳和重排适配，不靠整体缩小、隐藏必要操作或无理由横向滚动。明确滚动区域、sticky 基准、溢出边界和操作区。
- 使用代表性桌面宽度和窄屏检查长内容、表格、表单与浮层；交互不能只依赖 hover。

## 浏览与编辑

- 浏览态展示整理后的列表、摘要、详情和状态，通过明确入口进入创建或编辑，不让全部控件常驻。
- 高频单字段或立即生效偏好可以行内编辑；上下文短任务优先 Dialog，较多详情和辅助任务考虑 Sheet，长表单、多步骤、独立链接或持久草稿使用独立页面。
- 返回时按需求保留 Router query、分页、筛选和滚动上下文。
- 浮层具备标题、关闭或取消入口、合理宽高、滚动方案和焦点恢复；避免嵌套模态及小 Dialog 塞长页面。
- 未保存修改按实际风险保护，不给所有表单机械增加确认。

## 构图与拆分

- 标题、关键状态、主操作和主要内容形成阅读顺序；次要元数据和低频操作通过分组、菜单或渐进展示降低干扰。
- 可按任务复用 Sidebar、Card、Chart、Table 等本地组件，但不增加无业务价值的 Dashboard 统计。
- 页面私有组件只有在确实降低当前复杂度时才拆分；真实跨页面稳定复用后才提升到 custom，不按行数或假想复用拆文件。
