# 操作反馈与恢复

## 异步操作

- 异步写操作立即 pending 并防重复；vee-validate 使用 isSubmitting，Query mutation 使用响应式 pending，不虚构组件不存在的 loading prop。
- 按钮使用“保存中…”等明确文案并组合本地 Spinner，保持尺寸稳定。Spinner 可延迟防闪烁，但 pending 和防重复不能延迟。
- 只禁用冲突操作。首次加载使用贴近内容结构的 Skeleton，局部请求局部反馈，后台刷新保留已有内容和可用交互。
- 等待真实成功后再清空输入、关闭编辑或提示成功；失败保留输入、结束等待并恢复重试。
- 成功后按真实关系更新或失效 Query cache。乐观更新必须有取消、旧值保存、回滚和并发方案；前端防重复不替代服务端幂等。

## 结果反馈

- 保存、发送等没有明显页面内结果的操作通常用简短 Sonner Toast；收藏、开关等已有明确变化的操作可由控件反馈。搜索、筛选和后台刷新不逐次弹成功提示。
- 调用 `toast()` 前确认 App 已挂载唯一 Toaster；不另装第二套通知库。
- 字段错误就近展示，表单整体错误留在表单内，区域读取失败提供错误态和重试；持续需要阅读或修正的信息不能只放 Toast。
- 同一操作由一层负责提示，避免 mutation、页面和 interceptor 重复报错。API 传输层不 Toast、不跳转、不决定字段错误。
- 错误文案说明未完成动作、已知原因和下一步，不暴露异常栈、内部字段、状态码或敏感信息。

## 错误与危险操作

- AppErrorBoundary 只处理 Vue 可交给 `onErrorCaptured` 的后代组件错误，不代表已处理网络失败、Router 导航失败、Query error state、边界自身错误或所有 Promise rejection。
- 状态除颜色外结合文字、背景、边框、图标和 `aria-pressed` 等语义。
- 危险操作按真实后果选择确认或撤销，明确对象和后果，取消无副作用；普通操作不一律确认，不可逆操作不描述为可恢复。
