# 用户文案与表单

## 内容设计

- 使用目标用户的任务语言，同一对象称呼一致，不展示 API 字段名、数据库术语、内部枚举或研发说明。正式界面不混入“测试功能”“后续接入”等占位文案；真实能力限制说明原因与可用替代路径，不假装功能可用。
- 标题说明对象或任务，按钮说明动作，空态说明原因和下一步；删除重复介绍、含糊操作名和不必要字段，用默认值、自动推导及高级选项渐进展示减负，不让用户填写系统可确定的 ID 或技术配置。

## 输入与帮助

- `Input`、`Textarea` 的内容或格式不自明时提供简短 placeholder 示例，如“例如：每周采购清单”；不机械重复 label，也不用虚构个人信息作默认输入。placeholder 不替代可见 label、关键限制、单位或错误；适当使用单位附加区、Select、日期等控件减少自由输入。
- 低频解释优先 `LabelWithHelp` 或信息图标与 `Tooltip`；链接、交互或较长内容用 `Popover` 等适当组件，不把复杂交互塞进 Tooltip。
- 必需格式、费用影响和关键约束通过 `FieldDescription` 等直接可见，校验用关联字段的 `FieldError`；不把必要信息藏进悬浮提示，也不在标题或 label 下堆技术说明。
- 帮助入口支持键盘与窄屏，不仅依赖悬停；纯图标提供可访问名称。提交前后均能定位错误并理解修正方法，后端错误映射到字段；初始化和刷新遵循现有表单规则，不覆盖未保存输入。
