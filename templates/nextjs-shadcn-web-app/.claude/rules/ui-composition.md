# 布局与交互层次

## 桌面 Web 优先

- 默认按桌面任务效率、信息密度和多区域布局设计，移动端重排；产品明确面向其他设备时例外。Tailwind 的 mobile-first 写法不改变产品优先级。
- 列表和工作区合理利用宽屏，阅读和短表单限制行宽并合理对齐；用内容列、主次区域或侧面板组织真实内容，不困在手机容器中，也不为填满空间拉长文本、添加无用模块。
- 窄屏收纳与重排，不靠整体缩小、隐藏必要操作或无理由横向滚动适配。明确滚动区域、sticky 基准、溢出边界和操作区，以代表性桌面宽度（如 1440px、1920px）及窄屏检查长内容、表格和浮层。

## 浏览与编辑

- 浏览态展示整理后的列表、摘要、详情和状态，通过明确入口进入创建或编辑，不常驻全部编辑控件。分离交互职责，不强制拆文件；高频单字段和直接生效的偏好开关可行内编辑，不追加无收益的弹框或确认。
- 上下文内的短任务优先 `Dialog`；较多详情、辅助任务或对象参照考虑 `Sheet` 或侧面板。需同时操作底层页面时，选择并验证非模态模式。
- 长表单、多步骤、独立链接或持久草稿可用独立页面；提供返回入口并保留列表筛选、分页和滚动上下文，不照搬移动端逐屏推进。
- 浮层具备标题、关闭或取消入口、合理宽高和滚动方式，支持键盘并在关闭后恢复焦点；避免嵌套弹框和小弹框塞长页面，按风险保护未保存修改。

## 构图与操作

- 标题、关键状态、主操作和主要内容形成阅读顺序；次要元数据和低频操作用分组、菜单或渐进展示降低干扰。
- 主动采用适合任务的推荐组合，如工作台的 Sidebar、Card、Chart、Table，不添加无业务价值的统计。先精简内容、建立层级，再用图片、摘要、图标和图表改善理解，不以装饰掩盖组织问题。
