# Next.js：编码前务必阅读文档

在进行任何 Next.js 相关工作之前，请在 `node_modules/next/dist/docs/` 中找到并阅读相关文档。您的训练数据可能已经过时——文档才是权威来源。

## 阅读与导航

- 开始修改前，阅读任务直接触及的代码、调用方、相邻实现、相关测试和配置；不要仅凭目录名或已安装依赖推断能力已经存在。
- 初始化、环境、脚本和部署以 `README.md` 与 `package.json` 为准；格式和静态检查以实际配置为准。
- 进入包含子级 `AGENTS.md` 的目录时，先阅读并遵循子级规则。修改 `src/api/` 时，还必须阅读该目录的 `README.md`。
- 涉及 shadcn/ui 组件、样式、组合、注册表、预设或 `components.json` 时，使用可用的 shadcn skill，并先检查项目中的实际组件源码。不要在此重复 skill 的组件、样式、组合或 CLI 规则。

## 架构边界

- 保持模板业务中立。未经任务确认，不加入客户业务域、业务协议、领域示例数据，或为未来预建目录与抽象。
- 项目采用 Next.js App Router。根页面入口为 `src/app/page.tsx`，嵌套路由入口为 `src/app/<route>/page.tsx`；入口负责路由级数据获取、metadata 和页面组合。
- 页面默认保持 Server Component。只有事件处理、浏览器 API 或客户端 Hook 所需部分才进入最小客户端边界。
- 页面私有组件仅在页面确实需要拆分时创建，并就近放在同路由的 `_components/`；不要预建空目录。确认跨路由复用后，再提升到 `src/components/` 等共享位置。
- 只为已确认的应用级行为增加全局 Provider。已安装依赖不代表认证、国际化、全局状态、表单方案或 TanStack Query hooks 已接入。
- API 的目录职责、DTO、endpoint、协议适配、认证和错误策略只遵循 `src/api/AGENTS.md` 与 `src/api/README.md`；不要在根规则外猜测或补写这些约定。
- 优先复用现有代码、平台能力和已安装依赖。没有真实复用或变化点时，不增加共享层、包装层、新依赖或预留接口。

## UI 与 shadcn/ui

- 用户明确要求或设计参考优先；没有参考时，与相邻页面的层级、密度、间距和交互方式保持一致。
- 优先复用现有 UI 组件和语义化主题令牌，不为单个页面重复实现基础组件。页面复杂到需要拆分时，使用路由私有的 `_components/`；简单页面无需为形式拆分。
- 页面的一次性定制放在调用处或组合组件中。确有跨页面的组件级需求时，可以审查并修改 `src/components/ui/`，并同步验证受影响行为。
- UI 变更应覆盖响应式布局、亮暗主题和基本可访问性，包括语义结构、可访问名称、键盘操作和可见焦点。

## TypeScript 与质量

- TypeScript 严格模式已启用，使用现有的 `@/` 导入别名。类型、格式、lint 和导入整理以实际配置为准。
- 避免使用 `any` 或不安全断言掩盖未确认的数据契约；确有必要时缩小范围并说明边界。
- 保持改动聚焦；不要顺手重构无关文件，也不要加入推测性抽象、兼容层或依赖。
- 行为发生变化时，增加或更新覆盖该行为的最小相关测试；测试层级应与变更边界匹配。
- 优先在共享根因处修复问题，不要在多个消费方重复增加补丁。

## 验证与完成标准

- 使用 `package.json` 中已有的 pnpm 脚本；具体命令和完整验证矩阵以 `README.md` 为准。
- 代码变更至少执行类型检查、静态检查和直接相关测试。
- 影响构建配置、Server/Client 边界或生产运行行为时，执行构建验证；改变用户可见流程或交互时，执行对应的端到端验证。
- 模板发布或范围较大的升级，执行 README 中的完整本地验证序列。
- 交付时明确列出已执行、失败及因环境原因未执行的验证；不得将未运行表述为已通过。
