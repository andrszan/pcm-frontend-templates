## 阅读与导航

- 修改前阅读相关源码、调用方、相邻实现、测试和配置；进入有子级 `AGENTS.md` 的目录时先遵循子级规则。
- 初始化、环境、pnpm 命令和部署以 `README.md` 与 `package.json` 为准；格式和静态检查以实际配置为准。
- 按任务范围阅读以下规则，不必全文加载；UI/UX 设计阶段也应主动阅读相关主题，不等待源码路径触发加载：
  - 组件与样式：[UI 规则](.claude/rules/ui.md)。
  - 页面、创建编辑与响应式：[布局与交互层次](.claude/rules/ui-composition.md)。
  - 请求、提交与恢复：[操作反馈](.claude/rules/ui-feedback.md)。
  - 文案、字段与帮助：[内容与表单](.claude/rules/ui-content.md)。
  - 图标、动效、素材与依赖：[视觉表达](.claude/rules/ui-visual.md)。
  - Next.js 路由、组件边界或配置：[Next.js 规则](.claude/rules/nextjs.md)。
  - TypeScript 代码：[TypeScript 规则](.claude/rules/typescript.md)。
  - 页面结构、Zustand 和表单示例：[React 代码模式](.claude/rules/react-style.md)。
- 修改 `src/api/` 前阅读该目录的 `AGENTS.md` 与 `README.md`，API 分层和协议策略以这两份文档为准。

## 全局边界

- 优先复用现有实现、平台能力和已安装依赖；不新增未经确认的业务、模型、流程、协议或示例数据，不为假设的未来需求增加抽象、依赖或空目录。
- 已安装依赖不代表能力已接入；只为已确认的应用级行为增加全局 Provider，不默认引入认证、国际化或全局状态。
- 需求和现有业务契约优先；Skill 按需使用，缺失不阻塞，其建议不得覆盖实际证据、改变业务契约或扩大改动范围。
- `NEXT_PUBLIC_` 变量按公开客户端信息处理，不得保存 Token、密码、API Key 等敏感信息。
- 优先在共享根因处修复问题，不在多个消费方重复打补丁。

## UI/UX 工作方式

- 设计、实现和验收沿用相关产品要求与既有 UI/UX 框架；核对实际框架、客户端边界、组件 base、别名、主题入口和已接入能力，不把模板惯例当成产品设计。
- 跨页面框架问题使用可用的 `ui-ux-framework`，shadcn 实现与组合遵循 UI 规则，匹配场景参考时使用 `ui-component-patterns`；Skill 缺失时依据源码与官方资料继续，不猜组件 API。
- 积极复用成熟布局、推荐组合和组件参考，不为原创重写、不以组件数量衡量质量；反馈、信息层级、用户文案和桌面适配属于功能完成标准，不留作可选美化，也不借机重做无关页面。

## 验证与交付

- 代码变更至少执行 `pnpm type-check`、`pnpm lint` 和直接相关测试；完整验证序列见 README。
- 行为变化时增加或更新最小相关测试：纯逻辑和 API core 用 unit，Provider/Router 组合用 integration，用户可见流程、客户端导航和水合行为用 E2E。永久 E2E 用例按场景稳定性和长期回归价值选择。
- 影响构建、路由、Provider 或生产运行行为时执行 `pnpm build`；涉及生产运行差异时，还需通过 `pnpm start` 或等价生产环境验证，不能以开发服务器测试代替。
- 用户可见流程使用 Playwright 或等价真实浏览器完成任务并实际查看代表性截图；覆盖适用的桌面、窄屏、键盘、焦点、主题和 reduced motion，检查控制台、网络及服务状态。静态检查或截图本身不等于验收通过。
- 按本次行为检查等待、失败、重试、空态与长内容；写操作验证防重复提交、失败保留输入及成功同步，编辑验证取消、关闭和返回后的上下文。基础反馈或布局失效不得以构建成功代替完成。
- 依赖后端的最终验收必须连接真实后端和真实数据；Mock、模拟延迟或失败只用于局部测试。在现有需求或验收记录中简述主要交互选择及结果，不另建固定格式报告；列出已执行、失败和未验证范围，不把未验证表述为已通过。
