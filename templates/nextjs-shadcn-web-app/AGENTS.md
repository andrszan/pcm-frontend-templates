## shadcn 技能

所有涉及 shadcn/ui 组件、样式、组合、注册表、预设或 `components.json` 的工作，请使用 shadcn skills。

如果该skills不可用，请通过以下命令安装：

```bash
npx skills add shadcn/ui@shadcn --agent claude-code --yes
```

该技能包含组件、样式、组合、可访问性和 CLI 规则。请勿在此处重复这些规则。在使用本地组件之前，请始终检查其源代码。

请勿修改 `src/components/ui/` 内的文件。保持这些组件完整，并在使用它们的地方应用样式或自定义设置。

## 创建或扩展页面

1.  从截图或图像复现 UI 时，应紧密遵循其视觉方向，包括布局、层级、间距、组件结构和重要细节。使用项目现有的组件和语义化主题令牌来实现，而不是复制原始颜色值。如果设计需要当前主题令牌中没有的颜色，或者用户明确要求非主题色，请使用 Tailwind 默认调色板中的命名颜色。请勿使用任意的十六进制、RGB、HSL 或 OKLCH 值。
2.  将每个新页面拆分为路由 `_components/` 目录下专注的组件。保持 `page.tsx` 简洁，专注于组合这些部分。
3.  默认保持 `page.tsx` 为服务端组件。将交互性或浏览器相关的代码移入专用的客户端组件。
4.  在选择小部件之前确定信息层级。让内容决定页面结构。
5.  在合适的地方保持已有的视觉节奏：紧凑的间距、清晰的排版层级、响应式的操作行，以及在较小屏幕上能整齐折叠的网格。
6.  小部件的选择没有固定公式。尝试卡片、资源行、计量器、图表、标签页、空状态和操作的不同排列，然后保留最能清晰传达内容并与项目风格一致的版本。
7. 在卡片密度、边框、圆角、间距、内容宽度和响应行为上与附近的页面保持一致。
8. 使用语义化主题令牌，以便新页面能够兼容亮色模式、暗色模式和现有的主题预设。

## 代码约定

- TypeScript 严格模式已启用。请使用精确的类型，避免使用 `any`。
- 使用现有的 `@/` 导入别名。
- 遵循 Biome 配置：双引号、分号、两个空格缩进、排序后的导入以及 120 个字符的行宽。
- 避免不必要的依赖。
- 保持更改的专注性，不要重构不相关的文件。
