# 前端模版项目架构搭建说明文档

> **历史参考。** 本文记录当前项目形成时的架构选择和搭建顺序，不能作为新项目的初始化指南。当前项目请以 [README](../README.md) 和 [项目使用前置环境准备](项目使用前置环境准备.md) 为准。

## 当时的目标

建立一个不绑定具体业务的 Next.js App Router 基线，提供：

- TypeScript、Biome 与 Tailwind CSS；
- shadcn/ui 与亮暗主题；
- TanStack Query、Axios 与可扩展 API 基础层；
- React Hook Form、Zod、Zustand 和 TanStack Table，按真实页面需要启用；
- Vitest 与单浏览器 Playwright 本地 smoke test。

当前项目刻意不预设认证、Token 刷新、统一响应体、业务错误码、全局 Toast、重试、OpenAPI 生成、Docker、CI 或监控。这些能力必须由实际产品与后端契约触发。

## 关键架构选择

### App Router 与 Provider 边界

根布局保持 Server Component，以导出 Next metadata、加载字体和定义文档结构。所有需要浏览器状态的依赖集中在 `src/app/providers.tsx`：

- `ThemeProvider` 负责主题切换；
- `QueryClientProvider` 在组件生命周期内创建 QueryClient；
- 页面默认仍是 Server Component，只有交互边界才使用 `"use client"`。

这样避免模块级 QueryClient 在服务端请求间共享状态，也避免整棵根布局被发送到客户端。

### API 层

`src/api/core/` 只保存 Axios 与拦截器等通用基础设施；项目级 `src/api/client.ts` 统一装配基础地址、超时和未来明确的协议策略；真实业务出现后再在 `src/api/modules/<domain>/` 中按后端资源划分 endpoint 与 DTO。

目前仅有的公开环境变量是 `NEXT_PUBLIC_API_URL`。它可为空并使用相对 URL；由于会打包到浏览器，不能存放秘密。`src/env.d.ts` 只改善已知属性的编辑体验，不提供运行时校验或完整的拼写保护。

### UI 与样式

`src/components/ui/` 为 shadcn 生成组件，使用既有 `components.json` 与语义主题 token。应用页面通过现有组件和 token 组合，不为单一页面预建 feature、repository、service 或 DTO 层。

字体通过 `next/font` 注入 CSS 变量；`--font-sans` 必须指向 `--font-geist-sans`，不能自引用。

### 测试

- `tests/unit/api/api-client.test.ts` 覆盖 Axios 基础行为；
- `tests/integration/` 验证首页的基本渲染语义；
- `tests/e2e/` 仅通过本地 `baseURL` 验证 title 和首页主标题。

测试不访问第三方网站，也不为了占位而断言常量或无行为按钮。

## 历史搭建顺序

1. 选择 Next.js App Router、TypeScript、Tailwind CSS 与 pnpm。
2. 初始化 shadcn 配置并按实际需要添加 UI 组件。
3. 引入主题、Query、Axios、表单、状态与表格能力，但不创建空业务模块。
4. 建立 API core、项目级客户端和最小回归测试。
5. 将浏览器 provider 下沉至 `src/app/providers.tsx`，保持 layout 的服务端边界。
6. 配置一次性本地类型、lint、单测、构建和 Chromium smoke 验证。

历史搭建期间使用过 `create-next-app`、批量 shadcn 命令和临时生成脚本；这些步骤不应对当前项目重复执行，否则会覆盖现有配置、引入版本漂移或生成竞争锁文件。

## 表单示例的安全边界

登录、注册等包含密码的业务表单不属于当前基础项目。后续实现时，表单提交不得将完整数据对象写入 `console.log`、埋点或错误日志；只向确认的认证接口提交，并按产品安全要求处理失败信息。

## 部署说明

当前项目默认使用：

```bash
pnpm build
pnpm start
```

没有默认启用 `output: "standalone"`，也没有 Docker 流程。确认容器部署成为真实需求后，再启用 Standalone 并验证静态资源与 `public/` 复制流程。
