# 前端模版项目架构搭建说明

## 项目概览

本项目是一个基于现代化技术栈的 Next.js 前端模版，集成了完整的开发、测试、质量检查工具链。

**技术栈**：

- 框架：Next.js (App Router)
- 语言：TypeScript 5+
- 状态管理：Zustand + TanStack Query v5+
- UI 组件库：shadcn/ui
- 样式：Tailwind CSS
- 表单：React Hook Form + Zod
- 表格：TanStack Table
- HTTP 客户端：Axios
- 代码质量：Biome + TypeScript
- 测试：Vitest + React Testing Library

### 2.2 环境变量配置说明

#### 文件说明

项目使用两个环境变量文件：

| 文件           | 用途     | 说明                                   |
| -------------- | -------- | -------------------------------------- |
| `.env.example` | 模板文件 | 提交到 Git，供团队参考                 |
| `.env.local`   | 本地配置 | **不提交到 Git**（已在 .gitignore 中） |

#### .env.example（模板）

```bash
# --- 应用配置（NEXT_PUBLIC_ 前缀会暴露到客户端）---

# 后端 API 地址
NEXT_PUBLIC_API_URL=http://localhost:3000

# 应用名称
NEXT_PUBLIC_APP_NAME=ai-template-frontend

# 应用版本号
NEXT_PUBLIC_APP_VERSION=0.1.0
```

#### .env.local（本地开发）

```bash
# API 配置（本地开发）
NEXT_PUBLIC_API_URL=http://localhost:3000

# 应用配置
NEXT_PUBLIC_APP_NAME=ai-template-frontend
NEXT_PUBLIC_APP_VERSION=0.1.0
```

#### 重要说明

⚠️ **前缀 `NEXT_PUBLIC_` 的含义**：

- 这些变量会暴露到客户端代码中
- **不要存放敏感信息**（密钥、密码等）
- 仅用于可以公开的配置

#### TypeScript 类型声明

项目在 `src/env.d.ts` 中声明了所有环境变量的类型，提供以下能力：

- `process.env.NEXT_PUBLIC_*` 的 **自动补全**
- 拼写错误时的 **编译期提示**
- `NODE_ENV` 约束为 `"development" | "production" | "test"` 字面量类型

> 新增环境变量时，务必同步更新 `.env.example` 和 `src/env.d.ts`。

#### 配置步骤

**第一次 clone 项目时**：

```bash
# 1. 复制模板文件
cp .env.example .env.local

# 2. 根据本地环境修改 .env.local 的值
vi .env.local  # 或用你习惯的编辑器

# 3. 启动开发服务器时会自动加载 .env.local
pnpm dev
```

```typescript
  children,
```

### 3.6 配置 Axios HTTP 客户端

```typescript
import axios from "axios";

export const api = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_URL || "http://localhost:3000",
  timeout: Number(process.env.NEXT_PUBLIC_API_TIMEOUT) || 30000,
});

// 请求拦截器
api.interceptors.request.use(config => {
  const token = localStorage.getItem("auth_token");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// 响应拦截器
api.interceptors.response.use(
  response => response.data,
  error => {
    return Promise.reject(error);
  }
);
EOF
```

### 3.7 配置表单验证（React Hook Form + Zod）

**示例表单** `src/components/forms/LoginForm.tsx`：

```
mkdir src/components/forms
```

```typescript
cat > src/components/forms/LoginForm.tsx << "EOF"
"use client"

import { useForm } from "react-hook-form"
import { zodResolver } from "@hookform/resolvers/zod"
import { z } from "zod"
import { Button } from "@/components/ui/button"
import { Input } from "@/components/ui/input"

const loginSchema = z.object({
  email: z.string().email("Invalid email"),
  password: z.string().min(6, "Password must be 6+ characters"),
})

type LoginForm = z.infer<typeof loginSchema>

export function LoginForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<LoginForm>({
    resolver: zodResolver(loginSchema),
  })

  const onSubmit = (data: LoginForm) => {
    console.log(data)
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <Input {...register("email")} placeholder="Email" />
      {errors.email && <span>{errors.email.message}</span>}
      <Input {...register("password")} type="password" placeholder="Password" />
      {errors.password && <span>{errors.password.message}</span>}
      <Button type="submit">Login</Button>
    </form>
  )
}
EOF
```

## 五、配置 Next.js Standalone 输出

### 5.1 为什么需要 Standalone 模式

Next.js 的 `standalone` 输出模式会将应用打包为一个独立的 `.next/standalone/` 目录，包含所有运行所需的文件（包括精简的 `node_modules`），无需完整的 `node_modules` 就能运行。

这对 **Docker 部署** 至关重要：

- 镜像体积大幅减小（通常减少 80%+）
- 无需在运行镜像中安装依赖
- 启动速度更快

### 5.2 更新 next.config.ts

```typescript
cat > next.config.ts << "EOF"
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  // 关闭严格模式以避免开发中的双重渲染
  reactStrictMode: process.env.NODE_ENV === "production" ? true : false,
  output: undefined,            // 默认打包方式，支持npm run start部署启动
  // output: "standalone",
};

export default nextConfig;
EOF
```

### 5.3 构建产物

配置后，`pnpm build` 将生成以下关键产物：

```
.next/
├── standalone/        # 独立运行目录
│   ├── server.js      # 入口文件（node server.js 启动）
│   ├── node_modules/  # 精简的运行时依赖
│   └── ...
├── static/            # 静态资源（需手动复制到 standalone）
└── BUILD_ID           # 构建标识
```

`node .next/standalone/server.js` 启动服务

> **注意**：`public/` 目录和 `.next/static/` 不会自动包含在 standalone 中，需要在 Dockerfile 中手动复制。
