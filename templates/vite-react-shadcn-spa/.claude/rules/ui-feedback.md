# 操作反馈与恢复

## 异步操作

- 异步写操作立即 pending 并防重复提交；按钮默认显示“保存中…”等文案，文字右侧组合现有 `Spinner`，保持尺寸稳定，按本地 API 实现而不虚构 loading 属性。Spinner 可延迟显示防闪烁，pending 与防重复不能延迟。
- 只禁用冲突操作；长任务按真实能力提供进度、取消或后台提示，不伪造百分比。首次加载优先贴近内容结构的 `Skeleton`，局部请求区域提示，后台刷新保留已有内容和交互；失败结束等待并提供重试。
- 等待真实结果，不提前清空输入、关闭编辑或提示成功；失败保留输入并恢复重试，成功同步列表、详情和状态。乐观更新须处理回滚、并发与反馈，高风险操作不轻率采用；前端防重复不替代服务端幂等。

## 结果反馈

- 每个操作有可感知结果：保存、发送等通常使用简短成功 Toast，收藏、开关等明确即时变化可由控件反馈；搜索、筛选和后台刷新不逐次弹成功提示。
- 按实际组件 base 复用 Toast 并确认展示入口已接入，不另装重复能力，也不将普通成功做成需确认的 Dialog。
- 字段错误就近展示，表单整体错误留在表单内，区域读取失败提供错误态和重试；需持续阅读或修正的信息不能只放 Toast。同一操作由明确的一层负责提示，避免重复报错，API 传输层不依赖 React。
- 错误说明未完成的动作、已知原因和下一步，不编造原因或暴露异常栈、内部字段、敏感信息；关闭提示不等于问题解决。

## 状态与危险操作

- 状态切换除文字外，结合语义色、背景、图标填充或边框区分选中、未选中、进行中和不可用；保留文字或可访问状态语义，不仅依赖颜色。收藏可用 Star 描边与填充，提供名称及 `aria-pressed` 等语义；陌生业务动作保留文字。
- 危险操作按后果选择确认或撤销，明确对象和后果，取消无副作用；普通操作不一律确认，不可逆操作不描述为可恢复。
