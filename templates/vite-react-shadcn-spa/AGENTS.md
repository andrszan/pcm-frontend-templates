# 项目开发规则

## 阅读与导航

- 修改前阅读相关源码、调用方、相邻实现、测试和配置；进入有子级 `AGENTS.md` 的目录时先遵循子级规则。
- 初始化、环境、pnpm 命令和部署以 `README.md` 与 `package.json` 为准；格式和静态检查以实际配置为准。
- 按任务范围遵循以下规则，未自动加载时按需阅读，不必全文加载所有规则：
  - UI 实现或审查：[UI 规则](.claude/rules/ui.md)。
  - 路由、Provider、代理或部署：[Vite SPA 规则](.claude/rules/vite-spa.md)。
  - TypeScript 代码：[TypeScript 规则](.claude/rules/typescript.md)。
  - 页面结构、状态和表单示例：[React 代码模式](.claude/rules/react-style.md)。
- 修改 `src/api/` 前阅读该目录的 `AGENTS.md` 与 `README.md`，API 分层和协议策略以这两份文档为准。

## 全局边界

- 优先复用现有实现、平台能力和已安装依赖；不新增未经确认的业务、模型、流程、协议或示例数据，不为假设的未来需求增加抽象、依赖或空目录。
- 已安装依赖不代表能力已接入；只为已确认的应用级行为增加全局 Provider，不默认引入认证、国际化或全局状态。
- 需求和现有业务契约优先；Skill 按需使用，缺失不阻塞，其建议不得覆盖实际证据、改变业务契约或扩大改动范围。
- `VITE_` 变量按公开客户端信息处理，不得保存 Token、密码、API Key 等敏感信息。
- 优先在共享根因处修复问题，不在多个消费方重复打补丁。

## 验证与交付

- 代码变更至少执行 `pnpm type-check`、`pnpm lint` 和直接相关测试；完整验证序列见 README。
- 行为变化时增加或更新最小相关测试：纯逻辑和 API core 用 unit，Provider/Router 组合用 integration，用户可见流程和客户端导航用 E2E。永久 E2E 用例按场景稳定性和长期回归价值选择。
- 影响构建、路由、Provider 或生产运行行为时执行 `pnpm build`；涉及生产部署时另行验证路由回退、静态资源和 API 转发，不能以开发服务器测试代替。
- 用户可见流程变更使用 Playwright 或等价真实浏览器，覆盖适用的桌面、手机、关键交互和实际渲染结果，并检查相关控制台、网络和服务状态；静态检查或截图本身不等于验收通过。
- 依赖后端的最终验收必须连接真实后端和真实数据；Mock 只用于局部测试。交付时列出已执行、失败和因环境未执行的验证，不得把未验证表述为已通过。
